# NightHawk Vibe Coding 提示词库

以下提示词可以直接复制到 NightHawk TUI、`nighthawk -p` 或 VS Code 中使用。每条提示词都尽量包含：目标、范围、约束、验收标准。

## 1. 新功能开发

```text
请帮我实现一个 [功能名称]。

需求：
- [用户故事/行为]
- [输入输出]
- [技术约束，例如：使用 TypeScript、不要新增运行时依赖]

步骤：
1. 先阅读项目结构和现有代码风格。
2. 给出实现计划，等我确认后再写代码。
3. 编写实现与测试。
4. 运行相关测试并修复失败。

验收标准：
- [可观察结果]
- 所有相关测试通过
- 不破坏现有功能
```

## 2. 修复 Bug

```text
请定位并修复以下 Bug。

现象：
- [复现步骤]
- [期望行为]
- [实际行为]

要求：
1. 先找到根因，不要只改表面。
2. 解释根因和修复方案。
3. 写回归测试。
4. 运行测试确认。

约束：
- 不要改动无关代码。
- 如果修复会影响公共 API，请先说明。
```

## 3. 代码审查

```text
请审查当前分支的代码变更。

范围：
- [分支/文件/提交范围]

重点：
- 正确性
- 安全性（注入、路径穿越、密钥泄露等）
- 性能
- 可读性与项目风格
- 测试覆盖

输出格式：
1. 问题列表，按严重度排序。
2. 每个问题给出文件:行号、原因、修复建议。
3. 最后给一个总体结论。
```

## 4. 安全审计

```text
请对当前项目执行一次安全审计。

请依次执行：
1. SecurityScan：扫描整个工作区，按严重度输出。
2. SecretScan：查找硬编码密钥。
3. TaintTrace：对疑似用户输入到危险函数的数据流做追踪。
4. DepAudit：检查依赖风险。

重点检查：
- SQL 注入
- XSS
- 命令注入
- 路径穿越
- SSRF
- 反序列化
- 弱加密
- 认证/会话缺陷

输出：
- 每个发现的风险等级
- 证据 file:line
- 可执行的修复建议
```

## 5. 重构

```text
请重构 [模块/文件]。

目标：
- 提升可读性和可维护性
- 保持对外行为不变

约束：
- 不改变公共 API
- 保持现有测试通过
- 如果需要调整测试，先说明理由

流程：
1. 分析当前实现与调用方。
2. 给出重构计划。
3. 小步执行，每步运行测试。
4. 输出变更摘要。
```

## 6. 写测试

```text
请为 [模块/功能] 补齐测试。

要求：
- 覆盖正常路径、边界条件和错误路径
- 遵循项目现有测试风格
- 不要 mock 掉真正需要验证的集成点
- 运行测试并给出结果

验收标准：
- 新增测试全部通过
- 覆盖率达到 [目标，可选]
```

## 7. 从零开始一个项目

```text
请帮我从零搭建一个 [项目类型] 项目。

技术栈：
- [语言/框架/包管理器]

功能需求：
- [功能列表]

工程要求：
- 初始化 git
- 配置 lint/format/test
- 编写 README
- 提供一个最小可运行示例

流程：
1. 先给出目录结构和依赖清单。
2. 确认后开始创建。
3. 每一步运行验证命令。
```

## 8. 解释代码

```text
请解释 [文件/目录/函数] 的实现。

要求：
- 先给出一句话总结。
- 再按模块/函数拆解。
- 说明数据流、状态变化和边界条件。
- 指出潜在风险或改进点。
```

## 9. 性能优化

```text
请分析并优化 [热点/接口] 的性能。

方法：
1. 先定位瓶颈，用 profiling 或代码阅读。
2. 给出优化前后对比。
3. 保持正确性和兼容性。
4. 运行 benchmark 或测试验证。

约束：
- 不要牺牲可读性做微优化。
- 如果涉及架构变更，先讨论。
```

## 10. Vibe Coding 日常迭代

```text
继续完成当前任务。

当前状态：
- 已完成：[...]
- 下一步：[...]
- 阻塞：[...]

请：
1. 阅读相关代码。
2. 完成下一步。
3. 运行验证。
4. 更新 TODO 列表。
5. 简短汇报结果。
```

## 专业实现要点（开发流程视角）

### 需求分析

Vibe Coding 文档要把“自然语言开发”变成可重复、可验证、安全可控的工程流程。

### 设计决策

以提示词模板、阶段化工作流、安全审计清单为核心，让用户可以直接复制使用。

### 实现步骤

从项目准备 → 需求澄清 → 方案设计 → 小步实现 → 审查 → 安全审计 → 提交 → 迭代。

### 验证方式

每个提示词都要求 Agent 运行测试、lint、安全工具；文档本身引用 NightHawk 真实命令。

### 维护注意

提示词应随 NightHawk 工具集和权限模式演进，避免使用已废弃命令。
