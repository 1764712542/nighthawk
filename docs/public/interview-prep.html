2.2 引擎架构 — DI × Scope

agent-core-v2 的核心理念：依赖注入 × 生命周期作用域。

App → Workspace → Session → Agent
  • App：进程级单例，全局配置、插件、MCP 管理
  • Workspace：工作区级，文件系统、Git、MCP 连接池
  • Session：会话级，消息历史、Token 计数
  • Agent：Agent 级，工具注册、状态、Goal

规则：父作用域不能依赖子作用域，子作用域可以注入父作用域服务。

2.3 Agent 循环

User Input→ Plan→ Act (Tool Call)→ Observe→ Reflect→ Next Turn
  • Plan：Agent 输出思考链，决定下一步工具调用
  • Act：执行工具（Read、Edit、Bash、Grep 等）
  • Observe：观察工具返回结果
  • Reflect：根据结果调整计划，决定是否需要更多工具调用或生成最终回复

三、数据流

3.1 会话生命周期

创建 → Prompt → Turn 循环 → Close → 持久化
  • 创建：harness.createSession() → 初始化 Session 对象
  • Prompt：用户输入 → session.prompt() → 创建 Turn
  • Turn 循环：LLM 调用 → 工具调用 → 结果观察 → 下一轮
  • Close：session.close() → flushMetadata → triggerSessionEnd
  • 空会话（无 turn）不保存

3.2 工具调用流程

Agent → ToolSelection → resolveExecution → execute → observe → result
  • ToolSelection：LLM 选择工具和参数
  • resolveExecution：权限检查 + 审批（Permission Chain）
  • execute：实际执行工具操作
  • 权限模式：manual（需审批）、auto（自动批准）、yolo（跳过所有审批）

3.3 MCP 协议

MCP Server → Stdio/HTTP/SSE → McpConnectionManager → Agent Tool
  • 支持 3 种传输方式：stdio、http、sse
  • MCP Server 配置文件：mcp.json（用户级 + 项目级 + 插件级）
  • OAuth 认证流程：needs-auth 状态机

3.4 ACP 协议

IDE → ACP Client → nighthawk acp → JSON-RPC → Engine
  • IDE 通过 nighthawk acp 子进程接入
  • JSON-RPC over stdio
  • 支持：Zed、JetBrains（PyCharm/IntelliJ）、Paseo

六、系统设计决策

6.1 为什么选择 DI × Scope 而非传统 DI？

  • 传统 DI 容器只有一个全局作用域，无法处理多会话、多 Agent 的场景
  • 4 层 Scope 映射自然生命周期：App（进程）→ Workspace（工作区）→ Session（会话）→ Agent（Agent）
  • 子 Scope 自动继承父 Scope 的服务，无需手动注册
  • Scope 关闭时自动清理所有子 Scope 的资源

6.2 为什么 v1 和 v2 两套引擎？

  • v1（agent-core）：传统 DI 服务层，较早的设计，适合单会话场景
  • v2（agent-core-v2）：DI × Scope 架构，支持多会话、多工作区、多 Agent
  • v2 是当前主力引擎，v1 保留用于兼容旧版 ACP 和 TUI
  • SDK 层透明切换：SDKRpcClientV2 封装 v2 差异

6.3 为什么用 Node.js SEA 而非 pkg/nexe？

  • Node.js SEA 是官方方案，无第三方依赖
  • 原生支持 ESM、Worker threads、所有 Node.js API
  • 构建简单：node --experimental-sea-config + postject 注入
  • 跨平台支持：macOS、Linux、Windows

6.4 为什么自定义 TUI 框架而非 Ink/React-Terminal？

  • pi-tui 是全自研的终端 UI 框架
  • 零依赖：不依赖 React、JSX、虚拟 DOM
  • 直接操作终端缓冲区，极致性能
  • 完整的 Canvas、动画、事件系统
  • 支持真彩色、Unicode、鼠标事件
